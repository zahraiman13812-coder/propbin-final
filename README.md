# پراپ‌بین — نسخه بررسی و اصلاح‌شده

راهنمای اصلی این نسخه همین فایل و `TEST-AND-DEPLOY-FA.md` است. راهنمای قدیمی `README-PROPBIN-GITHUB.md` فقط برای سابقه نگهداری شده و در صورت تفاوت، دستورهای این نسخه اولویت دارند.

## اجرا

Node.js 22 LTS و npm نصب کنید. در پوشه پروژه:

```bash
npm ci
```

از `.env.example` یک کپی با نام `.env.local` بسازید. اتصال PostgreSQL، رمز مدیریت، دو کلید تصادفی متفاوت و تنظیمات ارسال ایمیل را وارد کنید. فایل حاوی رمز را در GitHub قرار ندهید. در نسخه تحویلی، `.env.local` قبلی عمداً قرار داده نشده است؛ تنظیمات خصوصی قبلی‌تان را جدا نگه دارید.

```bash
npm run db:setup
npm run dev
```

نشانی محلی: http://localhost:3000 — مدیریت: `/admin-login`

## بررسی خودکار

```bash
npm test
npm run test:db
npm run check:types
npm run build
```

یا همه با `npm run check`. تست دیتابیس در PostgreSQL تعبیه‌شده PGlite و بدون اتصال به دیتابیس واقعی اجرا می‌شود. `db:setup` برعکس، دیتابیس مشخص‌شده در `DATABASE_URL` را تغییر می‌دهد.

## معماری این نسخه

- Next.js App Router، React و PostgreSQL؛ نام بعضی فایل‌ها هنوز Supabase است اما اتصال از طریق `pg` انجام می‌شود.
- اطلاعات واقعی شرکت‌ها، مقالات، تنظیمات، نظرات و قرعه‌کشی از دیتابیس خوانده می‌شود. داده‌های نمونه همراه پروژه خودکار به دیتابیس وارد نمی‌شوند.
- تصاویر عمومی جدید در جدول `media_objects`، حداکثر ۲ MiB برای هر تصویر، ذخیره می‌شوند. این انتخاب نیاز به سرویس ذخیره‌سازی و کلید جدید ندارد و با پشتیبان دیتابیس حفظ می‌شود. برای حجم بالای تصاویر، مهاجرت به object storage مناسب‌تر است.
- تصاویر خصوصی قرعه‌کشی فقط از مسیر احرازهویت‌شده مدیر نمایش داده می‌شوند؛ پاسخ فهرست دیگر شامل همه تصاویر base64 نیست.
- ویرایش شرکت‌ها و مقالات از صفحات اختصاصی `/admin/firms` و `/admin/articles` انجام می‌شود. API قدیمی `/api/content` فقط ویرایش تنظیمات را می‌پذیرد و برای تغییر مجموعه‌ها پاسخ 410 می‌دهد؛ نوشتن روی فایل محلی حذف شده است.
- فایل‌های قبلی در `public/` حفظ شده‌اند. اگر از نصب قدیمی فایل‌های `.uploads` دارید، باید پیش از جابه‌جایی آن‌ها را جدا منتقل کنید؛ این پوشه در فایل ارسالی موجود نبود.
